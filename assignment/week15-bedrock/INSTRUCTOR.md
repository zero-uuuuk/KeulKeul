# 진행자 리허설과 수업 운영

## 목표와 범위

이 과제의 중심은 Bedrock 모델 호출과 Knowledge Bases의 연결 이해다. 참가자는 제공 코드로 요청·응답을 관찰하고 설정을 바꾼 이유를 설명한다. 논문 비교 서비스·LangGraph·GraphRAG·웹앱 개발은 필수 과제에 포함하지 않는다.

## 배포 전 리허설

1. 새 폴더에서 설치와 프로필 로그인을 수행한다. 새 전용 suffix와 계정 ID를 사용한다.
2. 생성한 01~04 고객 관리형 정책을 관리자가 검토·적용한다. 역할 작성 권한은 관리 성격이므로 공유 계정에서는 관리자가 전용 역할을 미리 준비하는 방식으로 조정한다. 콘솔 추가 조회 권한 요구는 정확한 작업별로 확인한다.
3. KB 없이 generate 두 출력 상한을 실행하고 실제 응답과 stopReason을 기록한다.
4. 저장소·업로드·콘솔 KB 연결·Sync·Retrieve를 참가자 신원으로 완주한다. 관리자 세션 성공으로 대체하지 않는다.
5. 직접 호출/RAG, 문서에 없는 질문, top-k 1/3을 실행한다. 결과 차이가 없으면 그 관찰을 그대로 안내한다. 결과를 맞추려고 가짜 응답을 만들지 않는다.
6. 가능하면 연습 코드만 수정해 재업로드·Sync 후 새 원문이 검색되는지 확인한다.
7. 실제 전용 자원 정리까지 완료하고 소요 시간·OS·CLI·모델·리전·문제 해결 내용을 기록한다.

실제 AWS 전체 실행은 제작 시점에 수행하지 않았다. 제작자 로컬 검사와 위의 실계정 리허설 결과를 구분한다.

## 시간 배분과 평가

설치·IAM·로그인은 사전 준비다. 본 실습 60~90분은 측정값이 아닌 준비 목표이며 생성·동기화 대기에 따라 조정한다. 모델 호출 15~20분, 수집·검색 25~35분, RAG와 비교 15~25분, 정리 10분 정도로 준비할 수 있다. 짧은 발표와 실제 실습 시간은 별도다.

보고서는 서비스의 화려함보다 요청 필드·토큰·Sync·원문·생성 입력·권한을 설명하는지 평가한다. RAG가 반드시 더 정확해야 하거나 top-k 3이 반드시 더 좋아야 하는 과제가 아니다. 문서에 없는 정보에 대한 적절한 보류와 실제 근거 판단도 평가한다.

## 공통 자료

연습 문서는 완전히 가상이다. 기존 동아리 Notion 페이지나 실제 일정·규정을 수정하지 않는다. 개인 문서·키·기존 프로젝트 설정은 배포하지 않는다. 이전 논문 실습의 config와 상태 파일도 복사하지 않는다. 각 실습은 별도 전용 이름을 사용한다.

Guardrails와 모델 커스터마이징은 발표에서 소개하는 확장 기능이며 이 코드가 생성·적용하지 않는다. 별도 Bedrock Agent를 생성할 필요가 없다.
